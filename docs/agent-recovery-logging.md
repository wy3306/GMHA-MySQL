# Agent 重启恢复与日志

Agent 在 Manager 尚未启动、网络暂时不可达或心跳流断开时，每 5 秒重新尝试连接（各候选地址连接超时为 5 秒），任务通道独立重连。心跳断线不会中断正在执行的任务。安装和升级会启用 systemd 开机自启；新服务文件关闭启动频率限制，仍以 5 秒间隔重启进程。

“手动拉起”会重新加载服务、清除失败限制、启用开机自启，再启动或重启 Agent。恢复成功必须收到本次操作后的新心跳。启动失败保留命令退出码，同时采集服务状态、最近 30 条 journal 和文件日志最后 8 KiB。心跳等待超时会再次采集诊断，可在恢复任务的 LastSSHOutput 中查看。

## 日志保留策略

日志位置是 **agent.yaml 所在目录/logs/agent.log**，默认 `/home/gmha/agent/logs/agent.log`。在读取配置之前初始化，所以配置缺失或解析失败也会写入日志。文件权限为 0600，包含启动版本、停止、连接成功、连接失败、重试和采集错误。不会输出完整配置或凭证。

- 单文件最大 10 MiB，达到大小后自动轮转。
- 最多保留 5 个历史文件，历史文件使用 gzip 压缩。
- 历史日志最多保留 7 天，写入/轮转触发清理。
- 保留量约为当前文件加 5 份历史文件（压缩前约 60 MiB）；轮转和异步压缩期间会有短暂额外占用，不是文件系统硬配额。
- 不依赖服务器安装 logrotate。正常程序日志仅写入这个受控文件，避免额外产生一份无界重定向日志。

进程尚未执行到日志初始化（例如二进制架构不匹配、动态链接器缺失、目录无法写入）和未捕获 panic 仍由 systemd journal 提供诊断。可查看 `systemctl status gmha-agent.service` 及 `journalctl -u gmha-agent.service -n 50 --no-pager`。不要将标准输出无限追加到其他文件。

## 集群状态

集群详情侧栏使用全体成员的心跳汇总，与 Agent 分页和实例筛选无关；离线、降级、未知或异常实例不会显示为正常。刷新接口失败显示“状态未知”。

## 更新现有环境

需要同时部署包含本次修复的 Manager（含前端）和 Agent。仅更新 Manager 不会给旧 Agent 增加文件日志或重连逻辑。已有机器可通过安装/升级流程重写服务文件；手动拉起可以清除已有 systemd 启动失败限制，但不会替换 Agent 二进制。更新后检查开机启用状态，并在维护窗口验证服务器重启、Manager 暂停和恢复后的新心跳。
